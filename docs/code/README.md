# Разбор кода проекта «Афиша мероприятий»

> **Важно:** управление афишей доступно только роли `Admin` (логин `admin` / пароль
> `admin`), обычные пользователи только смотрят. Пошаговое описание ролей —
> в [09-roles.md](09-roles.md). В документах 01–08 местами описан вариант
> «только автор» — актуальное поведение смотрите в 09 и в самом коде.

Этот набор документов объясняет **весь код проекта построчно** — так, чтобы на защите
можно было открыть любую строку и сказать, что она делает.

## Как читать

Каждый файл разобран в виде «код + комментарий к строке»:

```csharp
var builder = WebApplication.CreateBuilder(args); // 14 — создаёт приложение и читает конфигурацию
```

Число в начале комментария — номер строки в настоящем файле. Если строка очевидная
(`using`, `{`, `}`), она объясняется вместе с соседними. Для повторяющихся данных
(8 событий в `SeedData`) полностью разобран первый элемент, а у остальных перечислены
только отличия — структура у них одинаковая.

## Карта проекта

```
backend/Afisha.Api/
├── Program.cs                 входная точка, DI, JWT, middleware, маршруты
├── Models/                    Event, Venue, User — сущности БД
├── Data/                      AppDbContext, SeedData, AppDbContextFactory
├── Contracts/                 DTO-записи (record), которые уходят наружу
├── Validation/                FluentValidation + endpoint-фильтр + ProblemDetails
├── Auth/                      PBKDF2-хеш пароля, выпуск JWT, чтение claim'ов
├── Storage/                   сохранение постера (Guid, 5 МБ, jpg/png/webp)
├── Endpoints/                 auth, venues, events
└── Migrations/                три миграции EF Core (генерируются)

frontend/src/app/
├── app.config.ts              провайдеры приложения (router, HttpClient, interceptor)
├── app.routes.ts              маршруты и lazy loading
├── app.ts / app.html / app.css оболочка: шапка, навигация, подвал
├── core/                      модели, сервисы, guard, interceptor, утилиты
├── components/                карточка, список, фильтр
└── pages/                     список, событие, форма, вход, регистрация, 404
```

## Мини-словарь

| Термин | Простыми словами |
| --- | --- |
| **DTO** | Объект для передачи данных наружу. Отдельный от сущности БД, чтобы не отдавать лишнее. |
| **DI (внедрение зависимостей)** | Контейнер сам создаёт нужные классы и передаёт их в конструктор. |
| **DbContext** | Сессия работы с БД: таблицы, запросы, сохранение. |
| **Миграция** | Файл с SQL-изменениями схемы, сгенерированный из модели. |
| **HasData** | Способ засеять начальные данные прямо в миграцию. |
| **JWT** | Подписанный токен: сервер выдаёт, клиент присылает в `Authorization: Bearer`. |
| **ProblemDetails** | Стандартный JSON ошибки: `title`, `status`, `detail`, `errors`. |
| **Сигнал (Angular)** | Реактивная переменная; при изменении шаблон перерисовывается. |
| **httpResource** | Функция Angular, которая делает HTTP-запрос и отдаёт сигналы `value/error/isLoading`. |
| **Интерсептор** | Прослойка, которая меняет каждый HTTP-запрос (добавляет токен). |
| **Guard** | Проверка перед открытием маршрута (пускает только вошедших). |
